One request, two gates: session identity is not permission

Run a session through login, time and logout; then ask a subject to perform an action on an object. The server must get both gates right: establish an identity safely, then authorize this exact request.

Toy model: the readable labels below are not real session tokens, contain no secrets and never leave this page. Real session identifiers need cryptographic randomness, protected transport and server-side lifecycle controls.

1 · Session lifecycle workbench

Idle timeout is 4 minutes; absolute lifetime is 10 minutes after login. A protected request refreshes only the idle clock.
